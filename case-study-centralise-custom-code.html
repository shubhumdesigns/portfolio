The Problem

Custom code was scattered, untargeted, and dangerous

The existing RentCaffeine Configuration screen let you select a theme and add CSS or JS — and code would go to all properties under that theme. But there was no way to pick specific properties within a theme, no error checking before saving, and no way to pause or roll back code quickly.

No properties selector within a theme

Selecting a theme sent code to every property under that theme — all or nothing. There was no way to pick specific properties within a theme and apply code only to those.

No code validation

Bad code with syntax errors was saved silently and went live immediately, breaking property sites with no warning to the user.

No enable / disable switch

The only way to turn off code was to delete it completely — risky, slow, and final. No quick toggle to pause and test.

No change history

There was no record of who changed what or when. If something broke on a live site, tracing the cause was nearly impossible.

Manual property-by-property updates

For clients with hundreds of properties, users had to open each one individually and repeat the same change — very slow and error-prone.

Before — Previous Screen

What the screen looked like before

The original screen had no theme selector, no properties dropdown, no validation, and no enable/disable toggle. Code was saved directly with a single Save button — no safety at all.

What was missing
  • No properties selector — code applied to every property under the selected theme with no way to pick specific ones
  • No properties multi-select — impossible to target specific properties
  • No syntax check before saving — broken code went live silently
  • No enable / disable checkbox — had to delete code to stop it
  • No audit log — no record of who changed what or when
How Might We

How might we let teams target specific properties within a theme — not just the whole theme — while keeping live sites safe from broken code and giving teams full control to pause or roll back instantly?

Design Constraints

Limits we had to work within

Must fit inside the existing tool

The solution had to work inside the current Site Manager screen and navigation. We couldn't build a separate product or move users to a new place.

Must be safe for non-developers

Client success managers also use this screen — not just developers. The design had to prevent mistakes automatically, not rely on technical knowledge to avoid them.

Must work at scale — 2000+ properties

Enterprise clients manage thousands of properties across many themes. The theme and property selectors had to work cleanly at full scale without extra manual effort.

Who We Designed For

Three types of users, one shared screen

Designer
Needs to apply CSS only to properties using a specific theme. Does not want code landing on the wrong theme or having to repeat work property by property.
Developer
Writes JS code and handles urgent fixes. Needs to know if there are errors before code goes live, and needs a quick way to switch code off if something breaks.
Client Success Manager
Manages large client accounts. Needs a full record of every code change — who did it and when — so they can trace any problem and answer client questions with confidence.

Before & After

What changed for users

Before
  • No properties selector — selecting a theme sent code to every property under it. There was no way to target specific properties within a theme.
  • No code checking — bad code was saved without any warning and went live silently.
  • No enable / disable switch — code was either active or had to be fully deleted to remove it.
  • No change history — nobody could see who made changes or when they happened.
  • Had to open every property one by one to update code — very slow and tiring.
After
  • Properties selector — after picking a theme, a second dropdown shows all properties under it. You can select all or pick specific ones only.
  • Code validation — red alert when syntax is wrong; green alert when code is correct. Bad code cannot be saved.
  • Enable / disable checkbox — turn code on or off at any time without deleting it. Resident Portal applies to all portal themes automatically — no theme step needed.
  • Audit log — every save records the user ID and exact date and time automatically.
  • One update in one place saves ~80% of the manual work across all properties in a theme.

Design Screens — Step by Step

The final Figma designs — each step explained

The screens below show the complete redesigned Property Site flow. Each step builds on the previous one — making the path from intention to deployed code safe, targeted, and fully logged.

Step 1 — Choose scope
Pick Property Site or Resident Portal using the tab at the top. Resident Portal skips the theme selection step entirely — portal code automatically applies to all portal themes, so there is nothing extra to select.
Step 2 — Select theme
Choose a theme from the first dropdown (for example, Astra). The second dropdown then automatically shows only the properties that use that theme. You can tick all of them with Select All or pick individual ones.
Step 3 — Choose code type
Use the Custom CSS or Custom JS tab to choose what kind of code you are adding. The correct editor mode loads for whichever tab you pick.
Step 4 — Add code & validate
Type your CSS or JS into the editor. When you hit Save, the system checks for syntax errors. If there is a mistake, a red alert appears — "Please fix the syntax errors" — and the code is not saved. Fix the issue and save again. If the code is correct, a green alert confirms: "Syntax validated and saved successfully."
Step 5 — Enable code & save
Tick the Enable checkbox to make the code active, then hit Save. A green "Code Enabled" alert confirms it is live. To pause the code without losing it, simply untick Enable and save again — no deletion needed. Every save automatically records the user ID, date, and time in the Last Updated field.

Key Design Decisions

Why each part was built this way

Every decision came directly from a problem that users reported. Each feature targets one specific pain point — nothing was added just for the sake of it.

Theme selector Theme selection already worked before — picking Astra sent code to all Astra properties. The new addition is the properties dropdown that appears after theme selection, letting users pick specific properties within that theme rather than always hitting all of them.
Auto-filtered properties After selecting a theme, the properties dropdown shows only the properties using that theme. Users can select all or pick one by one. No manual searching or cross-referencing needed.
Resident Portal — no theme step The Resident Portal uses only one theme. Code added here is applied to all portal pages. The theme option was removed because it was not needed and could confuse users.
Save-time validation When Save is clicked, the system checks for syntax errors. If there is an error, a red alert is shown and the code is not saved. If the code is correct, a green alert confirms it.
Enable / disable checkbox Lets users switch code on or off at any time without deleting it. Perfect for urgent situations — if something breaks, switch it off in seconds to test. The code stays saved and ready to turn back on.
Automatic audit log Every time Save is clicked, the system records the user ID and exact date and time automatically. The record is always visible — no extra steps, no guessing who made the last change.

Edge Cases

What happens when things go wrong

If the code has errors, it will not be saved. This prevents broken code from going live.
To apply code to all properties in a theme, users can select “All” in one click.
The enable/disable option works like an on/off switch. Users can turn off code anytime without deleting it.
An audit log saves every change with user name and time, so all updates are tracked.
The Resident Portal uses one theme, so theme selection is removed and code applies automatically.
Design Principle — Safety First
  • The system is designed to prevent mistakes by default, not just warn users.
  • Red and green messages are easy to understand, so users don’t need to learn anything new.
  • The enable/disable toggle lets users fix mistakes in one click without developer help.
  • Selecting a theme first helps make sure code is applied to the right properties.

Trade-offs

What we gained and what we accepted

What we gained
  • Users can target specific properties within a theme
  • "Select All" allows quick updates for all properties
  • Validation prevents broken code from going live
  • The toggle allows users to turn code on/off without deleting it
What we accepted
  • Users must first select a theme and properties before adding code
  • Validation happens only on Save, not while typing
  • The process is slightly slower but more accurate
Why it was worth it
  • Extra steps help prevent code from being applied to the wrong properties
  • Improves safety and reduces errors
  • A few extra seconds can save hours of fixing issues
What could be better next
  • Add live validation while typing, not just on Save
  • Show a preview of affected properties before saving

Learnings

What I learned from this project

01
Users don’t always need one solution for everything. The old system applied code to all properties. This worked for global changes but made targeted updates difficult. Adding a property selector helped users choose exactly where to apply the code.
02
Extra steps can prevent mistakes. Asking users to select a theme and properties first may feel like extra work, but it helps avoid major errors. A few extra seconds can save a lot of time later.
03
Safe controls build confidence. The enable/disable toggle lets users test code safely. They can turn it off anytime without deleting it or needing developer help.
04
Tracking changes improves responsibility. When every change is recorded, users become more careful. This helps reduce mistakes and improves team behavior.
05
Smart defaults make work easier. The system automatically shows properties based on the selected theme. Users don’t need to remember everything, which makes the process simpler.
